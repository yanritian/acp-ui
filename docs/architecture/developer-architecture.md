## 数据流

### 1. 任务启动流程

```
用户输入目标
    ↓
OperatorApi.startTask()
    ↓
Tauri invoke('operator_start_task')
    ↓
Rust: 创建 OperatorTask
    ↓
Rust: 初始化 TaskStateMachine
    ↓
Rust: 发出 TaskCreated 事件
    ↓
返回 task_id 给前端
```

### 2. 审批流程

```
Agent 请求执行操作
    ↓
SecurityGuard 检查审批级别
    ↓
如果需要审批: 添加到 ApprovalQueue
    ↓
前端轮询 getPendingApprovals()
    ↓
用户点击 Approve/Reject
    ↓
OperatorApi.approve()
    ↓
Rust: 更新审批状态
    ↓
Agent 继续或停止执行
```

### 3. 文件修改流程

```
Agent 生成文件修改
    ↓
filePatchPreview() 生成 diff
    ↓
用户审批
    ↓
filePatch() 应用修改
    ↓
创建备份文件
    ↓
发出 FilePatchApplied 事件
```

## API 设计原则

### 1. 协议先行

- TypeScript 和 Rust 类型定义必须一致
- 使用 serde 序列化
- API 变更需要同步更新两端

### 2. 安全默认

- 默认审批策略: safe_default
- 敏感操作需要显式审批
- 路径边界强制验证

### 3. 错误处理

- 所有错误都有明确错误码
- 前端捕获所有错误
- 后端使用 Result 类型

## 扩展指南

### 添加新 Domain Pack

1. 创建 `src-tauri/src/domains/<domain>/`
2. 实现 `ProjectAnalyzer` trait
3. 添加检测和分析逻辑
4. 在 `mod.rs` 中导出
5. 添加对应的前端 API

### 添加新 Tauri 命令

1. 在 `commands.rs` 添加 `#[tauri::command]` 函数
2. 在 `lib.rs` 注册命令
3. 在 `operatorApi.ts` 添加调用
4. 添加对应测试

### 添加新事件类型

1. 在 `types.rs` 添加 `OperatorEventType` 变体
2. 在 `operator.ts` 同步添加
3. 在命令中发出事件
4. 添加事件处理逻辑
