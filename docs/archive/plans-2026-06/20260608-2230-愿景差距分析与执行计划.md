> 目标：将 ACP-UI 打造为类似 Codex/Claude Code/Trae/Qoder 的全能 Agent 客户端平台
> ACP = 控制与通讯协议（不是客户端，是协议层本身）
> 所有能力均可插拔：Skill / MCP / Hook / CLI
> 生成日期: 2026-06-08 22:30

## 第二部分：详细差距分析

### 一、Skill 系统（现状 🟡 → 目标：自进化 + 社区市场）

**现有代码**：
- `src/lib/skill-system/` — 4 个文件共 1009 行
  - `types.ts` (185行): SkillDefinition, SkillInvocation, SkillResult 类型
  - `skill-invoker.ts` (198行): 调用 Skill 的封装
  - `dev-flow-skills.ts` (577行): 预置的开发流程 Skill
  - `index.ts` (49行): 导出
- `src-tauri/src/skill_commands.rs`: Rust 端 Skill Tauri 命令

**缺失**：
1. **自进化双钩子**（OpenClaw 模式）：
   - Pre-execution hook: 执行任务前检查是否缺少 Skill → 自动生成
   - Post-execution hook: 执行任务后提取高频操作 → 沉淀为新 Skill
2. **Capability Evolver 元技能**：一个能修改其他 Skill 的 Skill
3. **Skill 市场**：ClawHub 模式的社区技能共享平台
4. **Skill 版本管理**：Skill 的迭代、回滚、A/B 测试
5. **Skill 运行时沙箱**：隔离 Skill 执行环境

### 二、MCP 集成（现状 🟡 → 目标：深度集成 + 运行时发现）

**现有代码**：
- `src-tauri/src/mcp_manager.rs`: MCP 服务器生命周期管理
- `src-tauri/src/mcp_client.rs`: MCP JSON-RPC 客户端
- `hermes_traits.rs` 定义了 `McpIntegrated` trait 但是死代码

**缺失**：
1. **运行时工具发现**：Agent 执行过程中自动发现并调用 MCP 工具
2. **MCP 工具注册表**：统一的前端 MCP 工具列表和搜索
3. **MCP 服务器热插拔**：运行时添加/移除 MCP 服务器无需重启

5. **MCP 与 Skill 联动**：MCP 工具可被封装为 Skill

### 三、Hook 系统（现状 🔴 → 目标：Agent 自运行/自检测/自修复/自思考）

**现有代码**：
- `src-tauri/src/hooks_executor.rs`: Rust 端 Hook 执行器（仅事件钩子）

**缺失**：
1. **自运行 Hook**：Agent 可自主触发定时任务（类似 Cron）
2. **自检测 Hook**：Agent 运行时自检（健康检查、性能监控）
3. **自修复 Hook**：检测到异常后自动修复（重启、回滚、切换策略）
4. **自思考 Hook**：Agent 在关键决策点触发反思（类似 Chain-of-Thought 外化）
5. **Hook 编排引擎**：Hook 之间的依赖、条件、循环
6. **Hook 可视化编辑器**：前端可视化配置 Hook 流水线

### 五、Token 优化（现状 🔴 → 目标：OpenClacky 级省 Token）

**现有代码**：
- `src/lib/agent-runtime/context-compactor.ts`: 上下文压缩
- `src/lib/agent-runtime/token-optimizer.ts`: Token 统计
- `src/features/plugins/TokenOptimizerPanel.vue`: 统计面板

**缺失**：
1. **KV Cache 管理**（OpenClacky 核心）：
   - 内容哈希缓存：相同 prompt 片段复用之前的 KV Cache
   - 上下文窗口滑动缓存：保留最近 N 轮的 KV 不丢弃
   - 目标：缓存命中率 > 90%
2. **智能模型路由**：
   - 简单任务路由到低成本模型（如 GPT-4o-mini）
   - 复杂任务路由到高能力模型（如 Claude Opus）
   - 基于任务复杂度自动评估（smart_router.rs 有三层评估但未接入）
3. **精简工具集**（OpenClacky 哲学）：
   - 核心工具控制在 16 个以内
   - 避免冗余 Tool Schema 消耗 Token
   - 按需加载工具（只有 Agent 需要时才注入）
4. **上下文压缩增强**：
   - 对话历史自动摘要（保留关键信息，丢弃细节）
   - 代码块智能截断（只保留相关部分）
   - 文件内容按需读取（500 行最优窗口）

### 七、Agent 蜂群（现状 🔴 → 目标：Ruflo 模式顶层蜂群）

**现有代码**：
- `src-tauri/src/swarm_orchestrator.rs`: 简单蜂群编排

**用户核心需求**（反复强调）：**调用 Codex & Claude Code 做最顶层的 Agent 蜂群，而不是它们启动 subagent**

**缺失**：
1. **5 种 Swarm 拓扑**（从 Ruflo 借鉴）：
   - Star（中心辐射）：一个 Leader Agent 分配任务
   - Chain（链式）：Agent A → B → C 流水线
   - Mesh（网格）：所有 Agent 互相通信
   - Tree（树形）：多层级 Agent 管理
   - Ring（环形）：Agent 轮流处理
2. **顶层 Agent 注册**：
   - 将 Codex CLI 注册为蜂群顶层 Agent（通过 stdio 调用 `codex` 命令）

   - 它们不是 subagent，而是**蜂群的 Queen/Worker**
3. **Adaptive Queen 机制**（Ruflo 的自愈蜂后）：
   - 当 Queen Agent 失败时自动选举新 Queen
   - 负载均衡：繁忙 Queen 自动分裂 Worker
4. **HNSW 向量记忆**：
   - 所有 Agent 共享的持久向量数据库

   - 跨会话、跨 Agent 的知识共享

3. **Ultracode 模式**：自动判断任务复杂度 → 触发 workflow
4. **上下文隔离**：每个并行 Agent 独立上下文窗口
5. **Workflow 可视化调试**：实时展示每个并行 Agent 的状态

## 第三部分：GLM5 执行计划（分 6 个 Sprint）

### Sprint 1：核心协议层 + CLI（2 周）

> 目标：让 ACP-UI 成为真正的协议层，而不只是客户端

**S1.1 — ACP 协议规范定义**（3天）

新建 `src/lib/acp-protocol/spec.ts`：
```typescript
// ACP Protocol Specification v1.0

export interface ACPCapabilities {
  version: string;                    // 协议版本，如 "1.0.0"
  features: ACPFeature[];             // 支持的特性列表
  maxSessions: number;                // 最大并发会话数
  supportsStreaming: boolean;         // 是否支持流式传输
  supportsMultiplexing: boolean;      // 是否支持多路复用
}

export interface ACPFeature {
  id: string;                         // 如 "skill.evolution", "mcp.discovery"
  version: string;
  required: boolean;                  // 连接双方都必须支持
}

// ACP Message（扩展 JSON-RPC 2.0）
export interface ACPMessage {
  jsonrpc: '2.0';
  id?: string | number;
  method?: string;                    // 请求方法
  params?: Record<string, unknown>;
  result?: unknown;
  error?: ACPError;
  // ACP 扩展字段
  sessionId: string;
  timestamp: number;
  source: 'client' | 'server' | 'agent';
  encryption?: {
    algorithm: 'aes-256-gcm';
    keyId: string;
    iv: string;
  };
}

export interface ACPError {
  code: number;
  message: string;
  data?: unknown;
}
```

新建 `src/lib/acp-protocol/server.ts`：
- ACP Server 模式：WebSocket 监听，接受其他 ACP 客户端连接
- 能力协商握手：连接时交换 ACPCapabilities
- 会话管理：创建/恢复/关闭会话
- 消息路由：将消息路由到正确的 Agent

**S1.2 — ACP CLI 工具**（3天）

新建 `src-tauri/src/cli.rs` 或独立 crate `acp-cli/`：
```
acp --version                           # 版本

```

CLI 实现方式：使用 `clap` crate，通过 Tauri IPC 或直接调用 Rust 模块。

**S1.3 — 能力协商 + 多路复用**（4天）

在 ACP Server 和 Client 中实现：
- 连接握手：双方交换 ACPCapabilities
- 特性降级：如果一方不支持某特性，自动降级
- 多路复用：一个 WebSocket 连接上运行多个会话（通过 sessionId 区分）
- 背压控制：当输出速度 > 消费速度时，暂停发送

// Pre-execution hook：任务开始前检查 Skill 缺失
async function preExecutionHook(task: TaskRequest): Promise<SkillCheckResult> {
  const requiredSkills = await analyzeRequiredSkills(task);
  const availableSkills = await skillInvoker.listAvailable();
  const missing = requiredSkills.filter(s => !availableSkills.includes(s));
  
  if (missing.length > 0) {
    // 自动生成缺失 Skill
    for (const skill of missing) {
      const generated = await capabilityEvolver.generateSkill(skill, task.context);
      await skillInvoker.register(generated);
    }
  }
  return { skillsLoaded: requiredSkills, generated: missing.length };
}

// Post-execution hook：任务完成后提取模式
async function postExecutionHook(result: TaskResult): Promise<void> {
  if (result.success) {
    // 提取成功操作模式
    const pattern = await extractOperationPattern(result);
    if (pattern.frequency >= 3) {
      // 高频操作沉淀为 Skill
      const skill = await capabilityEvolver.evolveSkill(pattern);
      await skillInvoker.register(skill);
    }
  }
}

// 支持 JS/TS 脚本定义工作流

export interface WorkflowScript {
  name: string;
  // 类似 .claudeworkflows.js 的脚本定义
  execute: (ctx: WorkflowContext) => Promise<WorkflowResult>;
}

export class DynamicWorkflowEngine {
  // 加载并执行工作流脚本
  async runScript(script: WorkflowScript, input: unknown): Promise<WorkflowResult> {
    const ctx = this.createContext(input);
    // 每个并行任务独立上下文（避免上下文爆炸）
    return script.execute(ctx);
  }
  
  // 百级并行：使用 Promise.allSettled + 并发控制
  async parallel(tasks: Task[], concurrency: number = 50): Promise<TaskResult[]> {
    const results = [];
    for (const batch of chunk(tasks, concurrency)) {
      const batchResults = await Promise.allSettled(
        batch.map(t => this.executeSingle(t))
      );
      results.push(...batchResults);
    }
    return results;
  }
}
