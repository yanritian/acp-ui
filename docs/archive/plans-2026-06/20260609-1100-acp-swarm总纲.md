# acp-swarm 总纲：异构 Agent 蜂群编排引擎

> **版本**: 1.0.0
> **最后更新**: 2026-06-09
> **定位**: Agent 的 Kubernetes，AI 的浏览器
> **一句话**: acp-swarm 不做 Agent，它让 Agent 像团队一样协作。

---

## 一、项目定位

### 1.1 acp-swarm 是什么

acp-swarm 是一个**异构 Agent 蜂群编排引擎**。它不直接执行任何任务——不写代码、不写小说、不训练模型、不生成图片。它只做一件事：**让多个 Agent 按照目标（Goal）协作，自动迭代直到目标达成。**

类比：

| 类比对象 | 它做什么 | 它不做什么 |
|---------|---------|----------|
| 浏览器 | 渲染 HTML/CSS/JS | 不生产网页内容 |
| Kubernetes | 编排容器 | 不构建应用 |
| **acp-swarm** | **编排 Agent** | **不执行具体任务** |

### 1.2 浏览器类比

acp-swarm 是 Agent 世界的浏览器。浏览器不关心你的网页是电商还是社交还是游戏——它只关心你遵守 HTML/CSS/JS/DOM 协议。acp-swarm 不关心你的 Agent 是写代码还是写小说还是训练模型——它只关心你的 Agent 遵守 ACP 协议。

```
┌──────────────────────────────────────────────────────────────┐
│                   上层应用（"网站"）                           │
│                                                              │
│   acp-dev        acp-story      acp-ml       acp-game        │
│   编程助手        创意工厂       ML研究平台    游戏开发         │
│   (Codex/Claude) (小说/漫画/视频)(训练/评估)  (Unity/数值)     │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                   acp-swarm 编排引擎（"浏览器"）              │
│                                                              │
│   Goal 分解  │  Worker 路由  │  Reconcile Loop  │  检查点回溯  │
│   Queen 选举 │  事件流推送   │  Token 预算管控   │  Git 隔离   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                   ACP 协议栈（"Web 标准"）                    │
│                                                              │
│   Worker Protocol │ Goal Protocol │ Event Protocol │ Embed   │
│   (Agent 怎么注册) (目标怎么定义)  (状态怎么推送)   (UI怎么嵌入)│
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                   传输层（"TCP/IP"）                          │
│                                                              │
│   stdio（本地CLI）│ WebSocket（远程）│ HTTP（云端API）         │
└──────────────────────────────────────────────────────────────┘
```

### 1.3 核心原则

1. **领域无关**: 编排引擎不包含任何领域逻辑。它不知道什么是"代码"、什么是"小说"、什么是"训练"。它只知道 Goal、Worker、CompletionCondition。
2. **协议优先**: 一切通过协议交互。新增一个垂直领域不需要改引擎代码，只需要实现协议。
3. **Goal 驱动**: 不给 Agent 分配"任务"（固定步骤），给 Agent 设定"目标"（完成条件）。Agent 自动迭代直到目标达成。
4. **执行器/评估器分离**: 干活的 Worker 和判断"做完了没"的评估器是不同角色。不能自己说自己做完了。
5. **可观测性**: 系统的所有状态通过统一事件流暴露。没有黑盒。

## 二、协议栈规范

### 2.1 Worker Protocol v1 —— Agent 怎么接入蜂群

**任何 Agent，只要实现以下 5 个接口，就能成为 acp-swarm 的 Worker。**

这是 acp-swarm 最重要的协议。它等价于"HTML 标签"——浏览器不认识你的网站内容，但认识你的标签。

#### 2.1.1 注册

```
POST /acp/worker/register
Content-Type: application/json

{
  "worker_id": "novel-writer-01",
  "worker_type": "novel-llm",
  "version": "1.0",
  "capabilities": {
    "skills": [
      {
        "name": "chapter-writing",
        "proficiency": 0.9,
        "avg_duration_ms": 30000,
        "required_permissions": ["write_workspace"]
      },
      {
        "name": "character-dialogue",
        "proficiency": 0.85,
        "avg_duration_ms": 15000,
        "required_permissions": ["write_workspace"]
      }
    ],
    "max_concurrency": 2,
    "max_context_tokens": 200000,
    "output_formats": ["markdown", "text", "structured"]
  }
}

Response:
{
  "status": "registered",
  "worker_id": "novel-writer-01",
  "heartbeat_interval_ms": 10000
}
```

#### 2.1.2 心跳

```
POST /acp/worker/heartbeat
Content-Type: application/json

{
  "worker_id": "novel-writer-01",
  "status": "idle",
  "current_load": 0,
  "active_goals": [],
  "memory_usage_mb": 512,
  "uptime_seconds": 3600
}

Response:
{
  "status": "ok"
}
```

Worker 必须每 `heartbeat_interval_ms` 毫秒发一次心跳。编排器连续 3 次未收到心跳，判定 Worker 失联，触发故障转移。

#### 2.1.3 接收 Goal

```
POST /acp/worker/goal/receive
Content-Type: application/json

{
  "goal_id": "goal-chapter-01",
  "description": "根据大纲生成第一章的详细情节，包含人物动机和内心独白",
  "iteration": 0,
  "feedback_from_last_iteration": null,
  "workspace_path": "/workspace/novel-project/",
  "git_branch": "worker/novel-writer-01/goal-chapter-01",
  "token_budget": 50000,
  "timeout_ms": 300000
}

Response:
{
  "status": "accepted",
  "execution_id": "exec-001",
  "estimated_duration_ms": 25000
}
```

关键设计：
- `iteration`: 当前是第几轮迭代（从 0 开始）。第一轮是 0，如果未收敛，第二轮是 1，以此类推。
- `feedback_from_last_iteration`: 上一轮评估器的反馈。第一轮为 null，后续轮次包含"哪里不满足条件"的具体信息。
- `git_branch`: Worker 只能在这个分支上工作。这保证了并行 Worker 之间不会互相覆盖文件。

#### 2.1.4 汇报进度（可选）

```
POST /acp/worker/goal/progress
Content-Type: application/json

{
  "execution_id": "exec-001",
  "goal_id": "goal-chapter-01",
  "progress_pct": 65,
  "current_action": "Writing dialogue for scene 3 of 5",
  "tokens_used": 18000,
  "files_modified": ["chapter-01/scene-01.md", "chapter-01/scene-02.md"]
}

Response:
{
  "status": "ok"
}
```

这是可选接口。实现了它，UI 就能显示 Worker 的实时进度条。不实现，UI 只显示"执行中"。

#### 2.1.5 返回结果

```
POST /acp/worker/goal/result
Content-Type: application/json

{
  "execution_id": "exec-001",
  "goal_id": "goal-chapter-01",
  "success": true,
  "output": "第一章生成完毕，共 3200 字，5 个场景，12 段对话。",
  "tokens_used": 32000,
  "files_modified": [
    "chapter-01/scene-01.md",
    "chapter-01/scene-02.md",
    "chapter-01/scene-03.md",
    "chapter-01/scene-04.md",
    "chapter-01/scene-05.md"
  ],
  "tool_calls": ["file_write", "file_write", "file_write", "file_write", "file_write"],
  "git_commit_hash": "a1b2c3d4"
}

Response:
{
  "status": "received",
  "next_action": "evaluating"
}
```

编排器收到结果后，自动进入评估阶段（运行 CompletionCondition），Worker 等待下一轮指令。

#### 2.1.6 Worker SDK

为了降低接入门槛，提供两种语言的 SDK：

**Rust SDK**（给原生 Agent 用）：

```rust
use acp_worker_sdk::{Worker, WorkerConfig, GoalHandler};

#[tokio::main]
async fn main() {
    let config = WorkerConfig {
        worker_id: "my-agent-01".into(),
        worker_type: "custom".into(),
        orchestrator_url: "http://localhost:9090".into(),
        skills: vec![/* ... */],
        max_concurrency: 2,
    };

    let mut worker = Worker::new(config);

    worker.on_goal(|goal| async move {
        // 你的 Agent 逻辑
        let result = my_agent_execute(&goal.description).await;
        Ok(result)
    });

    worker.start().await;
}
```

**Python SDK**（给 ML/数据科学 Agent 用）：

```python
from acp_worker import Worker, WorkerConfig

config = WorkerConfig(
    worker_id="ml-trainer-01",
    worker_type="pytorch-trainer",
    orchestrator_url="http://localhost:9090",
    skills=[{"name": "model-training", "proficiency": 0.9}],
    max_concurrency=1,
)

worker = Worker(config)

@worker.on_goal
async def handle_goal(goal):
    # 你的训练逻辑
    result = await train_model(goal.description, goal.workspace_path)
    return result

worker.start()
```

**TypeScript SDK**（给 Node.js Agent 用）：

```typescript
import { Worker, WorkerConfig } from '@acp-swarm/worker-sdk';

const config: WorkerConfig = {
  workerId: 'comic-gen-01',
  workerType: 'image-generator',
  orchestratorUrl: 'http://localhost:9090',
  skills: [{ name: 'panel-generation', proficiency: 0.85 }],
  maxConcurrency: 4,
};

const worker = new Worker(config);

worker.onGoal(async (goal) => {
  const panels = await generateComicPanels(goal.description);
  return { success: true, output: panels, filesModified: panels.map(p => p.path) };
});

await worker.start();
```

### 2.2 Goal Protocol v1 —— 目标怎么定义

**所有 .goal 文件遵守同一 Schema。不管是编程、写小说、训练模型还是做游戏。**

#### 2.2.1 .goal 文件完整 Schema

```yaml
# ========================================
# acp-swarm Goal Definition Language v1
# ========================================

# 元数据
name: string (required)           # 任务名称
description: string (optional)     # 详细描述
version: string (default: "1.0")  # 文件版本
author: string (optional)         # 作者
tags: string[] (optional)         # 标签（用于搜索/分类）

# Worker 声明
workers:                          # 本任务使用的 Worker 列表
  - id: string (required)         # Worker 标识（引用已注册的 Worker）
    type: string (required)       # Worker 类型（用于自动发现）
    fallback: string (optional)   # 备选 Worker ID（主 Worker 不可用时）

# Goal 列表
goals:                            # Sub-Goal 列表
  - id: string (required)         # 唯一标识
    executor: string (required)   # Worker ID（必须是 workers 中声明的）
    description: string (required) # 任务描述（Worker 看到的指令）

    # 完成条件（核心）
    condition: (required)
      # 8 种条件类型，见 2.2.2

    # 评估器（可选）
    evaluator: (default: auto)
      # 4 种评估器类型，见 2.2.3

    # 依赖（可选）
    depends_on: string[]          # 必须先 Converged 的 Goal ID

    # 预算（可选）
    budget: number (default: 100000)  # Token 预算
    max_iter: number (default: 10)    # 最大迭代轮数
    timeout_ms: number (default: 300000) # 单轮超时

    # 检查点（可选）
    checkpoint: string (default: "on_converge")
      # never | on_converge | always

# 顶层 Goal（定义整体完成条件）
top: (required)
  condition: (required)           # 同 Goal 的 condition
  evaluator: (default: auto)
```

#### 2.2.2 完成条件类型（8 种）

```yaml
# 类型 1: 命令成功
condition:
  run: "npm test"                 # 执行的命令
  expect: "exit_code == 0"       # 期望结果
  cwd: "./frontend"              # 执行目录（可选）
  env:                           # 环境变量（可选）
    NODE_ENV: "test"

# 类型 2: 输出包含
condition:
  run: "npm run lint"
  output_contains: "0 errors"
  case_sensitive: false

# 类型 3: 输出匹配正则
condition:
  run: "npm run coverage"
  output_matches: "Statements\\s*:\\s*(8[0-9]|9[0-9]|100)\\."

# 类型 4: 文件检查
condition:
  file: "docs/api/auth.md"
  contains: "# Authentication API"   # 内容包含（可选）
  matches: "^# .+"                   # 内容正则（可选）
  max_size: 1048576                  # 文件大小上限（可选）

# 类型 5: HTTP 健康检查
condition:
  http: "http://localhost:3000/api/health"
  method: "GET"
  status: 200
  body_contains: "ok"

# 类型 6: 所有子条件满足（AND）
condition:
  all:
    - run: "cargo test"
      expect: "exit_code == 0"
    - run: "cargo clippy"
      expect: "exit_code == 0"
    - file: "target/doc/index.html"

# 类型 7: 任一子条件满足（OR）
condition:
  any:
    - run: "python test_v1.py"
      expect: "exit_code == 0"
    - run: "python test_v2.py"
      expect: "exit_code == 0"

# 类型 8: 自定义评估（POST 到指定 URL）
condition:
  custom: "http://localhost:8080/evaluate"
  method: "POST"
  # 编排器会 POST { goal_id, workspace_path, files_modified } 到此 URL
  # 期望返回 { "converged": true/false, "feedback": "..." }
```

#### 2.2.3 评估器类型（4 种）

```yaml
# 类型 1: 自动评估（默认）
evaluator: auto
# 直接运行 condition 中的命令，根据结果判定

# 类型 2: Queen 评估（主观判断）
evaluator: queen
# 先跑 auto，通过后让 Queen Worker 做主观审查
# 适用于：代码质量、架构合理性、文学质量

# 类型 3: 对抗性评估
evaluator:
  adversarial: "claude-reviewer-01"
# 让另一个 Worker 审查。不能等于 executor

# 类型 4: 混合评估
evaluator:
  hybrid:
    auto_condition:
      run: "npm test"
      expect: "exit_code == 0"
    human_evaluator: queen
# 先跑客观检查，通过后交主观评估
```

#### 2.2.4 完整示例：各垂直领域

**编程领域 .goal 文件：**

```yaml
name: Fix All TypeScript Errors
tags: [coding, typescript, bugfix]

workers:
  - id: claude
    type: claude-code

goals:
  - id: fix-errors
    executor: claude
    description: "Fix all TypeScript compilation errors reported by vue-tsc"
    condition:
      run: "npx vue-tsc --noEmit"
      expect: "exit_code == 0"
    budget: 80000
    max_iter: 5
    checkpoint: on_converge

top:
  condition:
    run: "npx vue-tsc --noEmit"
    expect: "exit_code == 0"
```

**创意写作领域 .goal 文件：**

```yaml
name: Generate Chapter 01 with Consistency Check
tags: [creative, novel, chapter]

workers:
  - id: novelist
    type: novel-llm
  - id: reviewer
    type: claude-code

goals:
  - id: outline
    executor: novelist
    description: "根据总纲生成第一章详细大纲，包含每个场景的起承转合"
    condition:
      all:
        - file: "chapter-01/outline.md"
          contains: "场景"
        - run: "python check_outline_structure.py chapter-01/outline.md"
          expect: "exit_code == 0"
    budget: 20000
    max_iter: 3

  - id: content
    executor: novelist
    description: "根据大纲写第一章完整内容，每个场景至少500字"
    condition:
      all:
        - file: "chapter-01/content.md"
          matches: "字数统计[：:]\\s*([3-9]\\d{3}|[1-9]\\d{4,})"
        - run: "python check_character_consistency.py chapter-01/"
          expect: "exit_code == 0"
    depends_on: [outline]
    budget: 50000
    max_iter: 5

  - id: review
    executor: novelist
    description: "文学质量审查"
    condition:
      custom: "http://localhost:8080/novel-quality-review"
    evaluator:
      adversarial: reviewer
    depends_on: [content]
    budget: 15000
    max_iter: 2

top:
  condition:
    all: [$outline, $content, $review]
```

### 2.3 Event Protocol v1 —— 状态怎么推送

**编排器在执行过程中持续发出事件流。所有 UI（Web Dashboard、CLI、Flutter App、第三方工具）从同一个事件流消费数据。**

#### 2.3.1 传输方式

事件流通过以下任一方式推送：

| 方式 | 适用场景 | 协议 |
|------|---------|------|
| WebSocket | Web Dashboard、实时 UI | `ws://host:port/acp/events` |
| Server-Sent Events | 轻量级客户端、curl 调试 | `GET /acp/events` (SSE) |
| Tauri Events | 桌面应用内部 | `listen("acp-event", handler)` |
| Polling | 不支持长连接的场景 | `GET /acp/events?since=timestamp` |

#### 2.3.2 事件类型完整列表

```typescript
// 所有事件遵循统一格式
interface AcpEvent {
  type: string;          // 事件类型
  timestamp: number;     // Unix 毫秒时间戳
  task_id: string;       // 所属任务 ID
  data: Record<string, unknown>;  // 事件数据
}

// ========== Worker 生命周期 ==========

// Worker 注册成功
{
  type: "worker.registered",
  data: {
    worker_id: "claude-01",
    worker_type: "claude-code",
    skills: ["code-generation", "code-review", "architecture"],
    max_concurrency: 2,
    registered_at: 1717891200000
  }
}

// Worker 心跳
{
  type: "worker.heartbeat",
  data: {
    worker_id: "claude-01",
    status: "busy",           // idle | busy | error
    current_load: 1,          // 当前执行的 Goal 数
    active_goals: ["goal-003"],
    memory_mb: 1024
  }
}

// Worker 失联
{
  type: "worker.disconnected",
  data: {
    worker_id: "codex-01",
    reason: "heartbeat_timeout",  // heartbeat_timeout | process_exit | network_error
    last_seen: 1717891260000
  }
}

// Worker 恢复
{
  type: "worker.reconnected",
  data: {
    worker_id: "codex-01",
    downtime_ms: 45000
  }
}

// ========== Goal 生命周期 ==========

// Goal 提交
{
  type: "goal.submitted",
  data: {
    goal_id: "goal-001",
    parent_goal_id: null,       // null = 顶层 Goal
    description: "Fix all TypeScript errors",
    executor: "claude-01",
    depends_on: [],
    token_budget: 80000,
    max_iterations: 5
  }
}

// Goal 开始执行
```

### 3.3 Git Workspace 隔离

每个 Worker 在独立的 Git 分支上工作，Goal Converged 后 Queen 合并到 main：

```
main (合并后的代码)
  ├── worker/claude-01/goal-001   (Claude Code 写前端组件)
  ├── worker/codex-01/goal-002    (Codex 写后端 API)
  └── worker/gemini-01/goal-003   (Gemini 写文档)
```

```rust
// 编排器在分配 Goal 前自动创建分支
pub async fn prepare_workspace(&self, goal: &Goal) -> Result<String, String> {
    let branch = format!("worker/{}/{}", goal.executor, goal.id);
    
    // 从 main 创建新分支
    Command::new("git")
        .args(["checkout", "-b", &branch, "main"])
        .current_dir(&self.workspace_root)
        .output()
        .await?;
    
    Ok(branch)
}

// Goal Converged 后合并分支
pub async fn merge_converged_goal(&self, goal: &Goal) -> Result<(), String> {
    let branch = format!("worker/{}/{}", goal.executor, goal.id);
    
    // 切到 main
    Command::new("git")
        .args(["checkout", "main"])
        .current_dir(&self.workspace_root)
        .output()
        .await?;
    
    // 合并 Worker 分支
    let output = Command::new("git")
        .args(["merge", "--no-ff", &branch, "-m", &format!("Merge {}: {}", goal.id, goal.description)])
        .current_dir(&self.workspace_root)
        .output()
        .await?;
    
    if !output.status.success() {
        // 合并冲突 → 创建冲突解决 Goal
        return Err("Merge conflict detected, creating resolution goal".into());
    }
    
    Ok(())
}
```

```rust
/// 根据历史执行数据自动校准 Worker 能力评分
pub fn recalibrate_worker_skills(&self) {
    let executions = self.db.get_recent_executions(100);
    
    for (worker_type, skill_name) in self.get_all_worker_skills() {
        let relevant: Vec<_> = executions
            .iter()
            .filter(|e| e.executor_type == worker_type && e.goal_template.contains(&skill_name))
            .collect();
        
        if relevant.len() < 5 { continue; }  // 样本不足，不校准
        
        let avg_iterations: f32 = relevant.iter().map(|e| e.iterations as f32).sum::<f32>() / relevant.len() as f32;
        let convergence_rate: f32 = relevant.iter().filter(|e| e.converged).count() as f32 / relevant.len() as f32;
        let avg_tokens: f32 = relevant.iter().map(|e| e.tokens_used as f32).sum::<f32>() / relevant.len() as f32;
        
        // proficiency = convergence_rate * (1 / avg_iterations) 归一化
        let new_proficiency = (convergence_rate / avg_iterations.max(1.0)).min(1.0);
        
        self.update_skill_proficiency(&worker_type, &skill_name, new_proficiency);
    }
}
```

### 4.3 智能推荐

```rust
/// 用户提交 Goal 时，推荐历史上表现最好的模板和 Worker
pub fn recommend_goal_config(&self, description: &str) -> GoalRecommendation {
    // 1. 语义匹配：找到历史上最相似的 Goal 描述
    let similar = self.find_similar_goals(description, top_k=5);
    
    // 2. 统计哪个 Worker 类型在这些相似 Goal 上表现最好
    let best_worker = similar
        .iter()
        .filter(|g| g.converged)
        .group_by(|g| &g.executor_type)
        .max_by_key(|(_, group)| group.count())
        .map(|(worker_type, _)| worker_type.clone());
    
    // 3. 推荐预算（基于历史平均值 + 20% 余量）
    let avg_tokens = similar.iter().map(|g| g.tokens_used).sum::<u64>() / similar.len().max(1) as u64;
    let recommended_budget = (avg_tokens as f64 * 1.2) as u64;
    
    // 4. 推荐最大迭代（基于历史平均值 + 2 轮余量）
    let avg_iterations = similar.iter().map(|g| g.iterations).sum::<u32>() / similar.len().max(1) as u32;
    let recommended_max_iter = avg_iterations + 2;
    
    GoalRecommendation {
        best_worker,
        recommended_budget,
        recommended_max_iter,
        similar_goal_templates: similar.iter().map(|g| g.goal_template.clone()).collect(),
    }
}
```

## 七、给 GLM5 的执行纪律

1. **Phase 2 是整个项目的生死线**。如果最小 Goal 原型（单 Goal + 单 Worker + echo + Reconcile Loop）跑不通，停止一切后续工作，先解决这个问题。
2. **不要创建任何不在本总纲中的文件**。没有 `utils.rs`，没有 `helpers.ts`，没有 `common/`。
3. **每写一个 Rust crate 就跑 `cargo check -p <crate-name>`**。每写一个 TS 文件就跑 `npx vue-tsc --noEmit`。不要攒到最后一起验证。
4. **Worker SDK 的接口必须跟 Worker Protocol 完全对齐**。SDK 是对协议的封装，不是另一套 API。
5. **事件流是唯一的真相来源**。UI 显示的所有数据都来自事件流，不来自直接 API 调用。如果 Inspector 看不到，就等于不存在。
6. **测试跟功能一起 commit**。不要"先写功能后补测试"。每个 Phase 的 commit 包含对应的测试。
7. **.goal 示例文件必须能真的跑通**。hello-swarm.goal 不是示例代码，是集成测试。
8. **不要碰任何不在 DELETE 清单中但也不在 KEEP 清单中的文件**。如果有不确定的，先问。
