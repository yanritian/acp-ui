### 任务 1.1：修复 `goal_graph.rs` 的 `remove_goal()` 逻辑 BUG [HIGH]

**文件**: `src-tauri/src/goal_graph.rs` 第 260-283 行

**问题**: 第 264 行先执行 `self.dependencies.remove(id)` 删除了依赖条目，然后第 267 行 `self.dependencies.get(id)` 试图读取已被删除的键，永远返回 `None`。结果是：被删 Goal 的上游依赖的 `dependents` 映射中永远不会清理指向该 Goal 的反向引用。

**修复方案**:
```rust
pub fn remove_goal(&mut self, id: &str) -> Option<Goal> {
    if let Some(goal) = self.goals.remove(id) {
        // 先取出依赖列表（不要先删）
        if let Some(deps) = self.dependencies.remove(id) {
            for dep in &deps {
                if let Some(rev) = self.dependents.get_mut(dep) {
                    rev.retain(|r| r != id);
                }
            }
        }

        // 清除该 Goal 在别的 Goal 的依赖列表中的引用
        for deps in self.dependencies.values_mut() {
            deps.retain(|d| d != id);
        }

        // 清除该 Goal 在 dependents 中的条目
        self.dependents.remove(id);

        Some(goal)
    } else {
        None
    }
}
```

**验证**: 写一个单元测试：添加 A→B 依赖，删除 B，确认 A 的 dependents 中不再包含 B 的 ID。

### 任务 1.2：修复 `goal_evaluator.rs` 命令注入风险 [HIGH]

**文件**: `src-tauri/src/goal_evaluator.rs` 第 71-75 行

**问题**: `CompletionCondition::CommandSuccess` 的 `command` 字段直接传给 `sh -c`，任何用户定义的命令都会被无条件执行。

**修复方案**:
```rust
fn eval_command(&self, command: &str, expected_exit_code: i32) -> EvaluationResult {
    // 命令白名单校验
    let allowed_prefixes = [
        "cargo ", "npm ", "npx ", "python ", "python3 ",
        "go ", "make ", "echo ", "cat ", "ls ", "grep ",
        "git ", "curl ", "wc ", "head ", "tail ", "diff ",
    ];

    let is_allowed = allowed_prefixes.iter().any(|p| command.starts_with(p));
    if !is_allowed {
        return EvaluationResult {
            passed: false,
            explanation: format!("Command blocked by allowlist: '{}'", command),
            details: vec![],
        };
    }

    // 禁止危险模式
    let denied_patterns = ["rm -rf", "sudo", "chmod 777", "> /dev/", "mkfs", "dd if="];
    if denied_patterns.iter().any(|p| command.contains(p)) {
        return EvaluationResult {
            passed: false,
            explanation: format!("Command contains dangerous pattern: '{}'", command),
            details: vec![],
        };
    }

    // 执行命令（带超时）
    let result = Command::new("sh")
        .arg("-c")
        .arg(command)
        .stdout(Stdio::piped())
        .stderr(Stdio::piped())
        .output();

    // ... 后续逻辑不变
}
```

**验证**: 单元测试覆盖：(1) 白名单内命令可以执行；(2) `rm -rf /` 被拒绝；(3) 无白名单前缀的命令被拒绝。

### 任务 2.7：修复 `kv-cache.ts` FNV-1a 哈希精度问题 [MEDIUM]

**文件**: `src/lib/token/kv-cache.ts` 第 52-64 行

**问题**: `Math.imul` 只产生 32 位结果，声称的 64 位哈希实际只有 32 位精度。

**修复方案**: 使用 BigInt 实现真正的 64 位 FNV-1a：
```typescript
private hashPrompt(prompt: string): string {
  const FNV_OFFSET_BASIS = 0xcbf29ce484222325n;
  const FNV_PRIME = 0x100000001b3n;
  const MASK_64 = 0xFFFFFFFFFFFFFFFFn;
  let hash = FNV_OFFSET_BASIS;

  for (let i = 0; i < prompt.length; i++) {
    hash ^= BigInt(prompt.charCodeAt(i));
    hash = (hash * FNV_PRIME) & MASK_64;
  }

  return hash.toString(16).padStart(16, '0');
}
```

function estimateTokens(text: string): number {
  let tokens = 0;
