### 1.2 剩余工作

**核心任务**：将 `src-tauri/src/goal.rs` 中的本地 Goal 类型替换为 acp-core 的 GoalRuntime。

#### 步骤 1：改写 src-tauri/src/goal.rs

当前本地 Goal 有 15 个字段，与 acp-core GoalRuntime 的 19 个字段存在如下差异：

| 本地 Goal 字段 | acp-core GoalRuntime 对应 | 差异说明 |
|---|---|---|
| `id` | `id` | 相同 |
| `description` | `description` | 相同 |
| `completion_condition: CompletionCondition` | `completion_condition: CompletionConditionSpec` | 类型不同，需统一 |
| `evaluator: Evaluator` | `evaluator: EvaluatorSpec` | 类型不同，需统一 |
| `assigned_worker` | `executor` | 字段名不同（有 serde alias） |
| `status: GoalStatus` | `status: GoalStatus` | acp-core 多一个 MaxIterReached 态 |
| `iterations` | `iteration_log` | 字段名不同（有 serde alias） |
| `max_iterations` | `max_iterations` | 相同 |
| `token_budget` | `token_budget` | 相同 |
| `token_used` | `tokens_used` | 字段名不同（有 serde alias） |
| `created_at` | `created_at` | 相同 |
| `started_at` | `started_at` | 相同 |
| `converged_at` | `converged_at` | 相同 |
| `parent_id` | `parent_goal_id` | 字段名不同（有 serde alias） |
| `dependencies` | `depends_on` | 字段名不同（有 serde alias） |
| — | `parent_task_id` | GoalRuntime 多出 |
| — | `current_iteration` | GoalRuntime 多出 |
| — | `per_iteration_timeout_ms` | GoalRuntime 多出 |
| — | `output_files` | GoalRuntime 多出 |

操作方式：
1. 删除本地 Goal、CompletionCondition、Evaluator、GoalStatus、IterationRecord、EvaluationResult、ConditionResult、GoalGraphSummary 定义
2. 改为 `pub use acp_core::{GoalRuntime as Goal, ...}` 的形式（与 swarm-engine/goal.rs 对齐）
3. 删除 to_runtime() / from_runtime() 桥接方法（不再需要）
4. 保留 GoalGraph 结构体（它是主应用独有的容器，但内部存储改为 GoalRuntime）
5. 更新 Tauri 命令的类型签名

#### 步骤 2：更新 GoalGraph 内部存储

当前 goal.rs 中有两个 GoalGraph 实现：
- `goal::GoalGraph`（goal.rs:665）— 使用 Mutex<HashMap>，被 Tauri 命令和 AppState 使用
- `goal_graph::GoalGraph`（goal_graph.rs:13）— 使用三个 HashMap，有 DAG 追踪能力，被 topology.rs 使用

统一为：保留 goal.rs 中的 GoalGraph（Tauri 命令使用的那个），内部存储类型从 `Goal` 改为 `acp_core::GoalRuntime`。goal_graph.rs 中的版本被 topology.rs 引用（7 处），但 topology.rs 自身的 `build_star_goals` / `build_chain_goals` 函数有 dead code warning。统一时需决定：如果保留 topology.rs 的拓扑执行能力，则 goal_graph.rs 需保留；否则可随 topology.rs 一起清理。

#### 步骤 3：更新 CompletionCondition / Evaluator 的 to_spec/from_spec

当前本地 CompletionCondition 和 Evaluator 有 `to_spec()` / `from_spec()` 方法做双向转换。统一到 acp-core 的 CompletionConditionSpec 和 EvaluatorSpec 后，这些转换方法不再需要。

#### 步骤 4：处理 GoalStatus 差异

acp-core GoalStatus 有 9 个变体（含 MaxIterReached），本地版本只有 8 个（MaxIterReached 映射为 Failed）。统一后：
- 前端 TS 类型需增加 `max_iter_reached` 状态
- 或保留当前映射（MaxIterReached → Failed）作为向后兼容

#### 步骤 5：编译验证

```bash
cargo check --workspace        # 确认编译通过
cargo test --workspace         # 确认所有测试通过
npx vue-tsc --noEmit           # 确认前端类型兼容
npx vitest run                 # 确认前端测试通过
```

### 1.3 风险

- **TS 前端兼容性**：serde alias 已覆盖字段名映射，但前端调用 Tauri invoke 时传递的 JSON 结构需确保与新类型匹配。建议在前端跑一遍完整流程测试。
- **GoalStatus MaxIterReached**：如果前端不认识这个新状态，需要在 status badge 中添加处理。
- **GoalGraph 双实例**：goal.rs 和 goal_graph.rs 有两个同名但不同的 GoalGraph。建议合并或明确职责边界。
