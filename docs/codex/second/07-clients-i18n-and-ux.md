# 客户端、一致性与多语言

## 1. 客户端职责

| 客户端 | 负责 | 不负责 |
|---|---|---|
| Web | 任务工作台、计划、事件、审批、记忆可视化 | 自行实现任务状态机 |
| Tauri | 本地桌面壳、本地能力桥接、安全配置 | 复制 Web 业务逻辑 |
| VSCode | 编辑器树视图、命令、工作区路径 | 自己保存任务事实 |
| IDEA | 工具窗口、IDE action、项目路径 | 自己发明另一套审批协议 |
| Remote API | 认证后的 HTTP/SSE 入口 | 绕过 Control Plane 直接执行工具 |

每个客户端必须使用相同的 task DTO、event DTO、approval DTO、error code 和 revision 语义。

## 2. 客户端一致性清单

每个客户端都必须支持：

- 连接、断开和健康状态。
- 任务列表和任务详情。
- 创建任务时传递 `domain`、`project_path`、`goal`、`mode`、`approval_policy`。
- 暂停、恢复、停止，并处理 `409 INVALID_TASK_STATE`。
- 读取事件和待审批项。
- 审批时传递 `task_id`、`approval_id`、`decision`。
- 连接失败、未授权、限流、任务不存在和 revision 冲突的可读反馈。
- 刷新后从服务端恢复，而不是从本地假状态恢复。

## 3. Web 交互规则

页面必须同时呈现：当前状态、当前步骤、下一步走向、记忆摘要、风险和操作员可执行动作。按钮状态由服务端状态和能力权限共同决定，不能只依据组件本地的 `isRunning`。

暂停、停止和拒绝操作要显示影响范围；高风险审批要显示 diff、文件列表、验证命令、操作者和过期时间。页面不能把等待状态写成“卡住”，要展示阻塞来源和恢复动作。

## 4. 多语言规则

Web 目前维护 13 个 locale：`en-US`、`zh-CN`、`zh-TW`、`pt-BR`、`de-DE`、`es-ES`、`fr-FR`、`ja-JP`、`ko-KR`、`vi-VN`、`th-TH`、`ms-MY`、`ru-RU`。

规则：

1. 新增用户可见文案先加 `src/locales/types.ts` 的 key，再补 13 个语言文件。
2. 组件只使用 `t('...')`，不能新增硬编码状态、按钮、标题和错误文案。
3. 默认语言 `en-US` 可同步启动；用户保存的语言必须在应用挂载前加载。
4. 缺失 key 使用明确 fallback，并在测试中暴露缺失，而不是静默显示 key 名。
5. 占位符、aria-label、tooltip、错误提示和空状态同样属于翻译范围。
6. 文案不能因为语言变长而破坏布局；必须做至少中文、英文、葡萄牙文三种视觉检查。

## 5. 客户端本地化

VSCode 和 IDEA 的菜单文本可以由各自平台提供，但任务状态、错误码和 Agent 输出不能依赖英文字符串。未来需要平台级 locale 文件时，key 必须与 Web 协议 key 保持一致，不能出现 `waitingApproval` 与 `waiting_approval` 两套业务含义。

## 6. 可访问性和响应式

键盘可以完成连接、创建、审批、暂停和停止；焦点在抽屉和确认框关闭后回到触发控件；状态变化有可读文本或 aria-live；移动窗口不发生按钮覆盖、文本溢出或状态遮挡。
