# ACP-UI 待解决问题（BUG / 功能缺陷 / 不可用项）

> 本文聚焦**直接影响功能使用**的问题——即用户能感知到的 bug、缺失、不可用、数据丢失等问题。
> 日期: 2026-06-05

---

## 一、数据持久化缺陷

### 1.1 对话消息刷新后丢失（已部分修复，需验证）

**现象**：用户在 Agent 对话中输入消息、收到回复后，刷新页面或关闭重开，之前的对话消失。

**影响范围**：Chat、Multi-Agent 页面。

**当前状态**：`session.ts` 中通过 `KVStore` 实现了 `saveMessages()`，但通过 `watch` 监听 `messages` 变化——确认在以下场景是否触发保存：
- 页面突然关闭（beforeunload 未处理）
- 移动端被系统杀死进程
- Web 版 localStorage 配额满

**建议验证方式**：进行一轮完整对话后，直接 `kill` 进程再重启，检查消息是否保留。

### 1.2 HistoryStore 纯内存问题（已修复，需回归测试）

**现象**：历史执行记录在 Web 版刷新后全部丢失。

**根本原因**：原实现注释写 "In-memory storage for now"。

**当前状态**：已引入 localStorage 持久化。需确认：
- 大量历史记录时性能是否下降（localStorage 同步操作阻塞 UI 线程）
- 移动端 WebView 的 localStorage 限额（通常 5-10MB）

### 1.3 会话列表不反映真实状态

**现象**：`savedSessions` 中保存的会话，如果在 agent 进程侧已被销毁（比如 agent 重启），前端仍显示为"可恢复"，用户点击恢复后报错。

**需要**：在恢复前做一次 `session/load` 的探活检查，如果 session 已不存在则标记为"已过期"而非直接报错。

## 二、Agent 连接稳定性

### 2.1 重连时机不完整

**现象**：当前重连只在移动端/Web 端的 `visibilitychange` 事件触发。以下场景不会重连：
- 桌面端：WebSocket 因网络波动断开（没有自动重试，只显示错误横幅）
- VPN 切换导致 IP 变化
- 电脑从休眠唤醒

**当前行为**：显示 "Reconnect" 按钮——用户需手动点击。

**需要的功能**：对于 WebSocket 类型的 agent，应实现指数退避自动重连（可配置开关），而不是只靠手动。

### 2.2 stdio agent 启动假死

**现象**：`npx @github/copilot-language-server` 首次启动需要下载包，stderr 长时间无输出时，前端只显示 "Starting..." 转圈，用户不知道是在下载还是卡死了。

**当前状态**：`detectPhase()` 函数能识别 downloading/installing/building/starting 四个阶段并显示不同进度文案，但：
- 如果 agent 输出完全不匹配这四个关键词，只显示 generic "Starting..."
- 没有超时提示（如"已等待 2 分钟，仍在下载中..."）

### 2.3 权限弹窗阻塞整个 UI

**现象**：agent 发出权限请求时，`PermissionDialog` 以模态弹窗出现，用户无法切换到其他页面（如 Traffic Monitor 查看上下文），只能二选一：批准或拒绝。

**需要**：权限请求应为非阻塞通知（如顶部横幅），允许用户先查看 Traffic Monitor 了解 agent 想做什么，再做决定。

## 三、模拟/不可用功能（用户可见但无法使用）

### 3.1 Hermes Dashboard —— 全部模拟数据

**路由**：`/hermes` → `HermesDashboard.vue`、`/collaboration` → `EnhancedHermesDashboard.vue`

**现象**：两个页面展示的 agent 状态、任务进度、协作网络图等，全部是 hardcode 的假数据，与真实 agent 状态不同步。

**用户困惑点**：用户同时在 Chat 页面与 agent 真实交互，但切换到 Hermes 面板看到的却是完全不相关的模拟数据。

**短期方案**：如果 Hermes 后端（`hermes/hermes-linux` 二进制）可用，将其接入真实数据；如果不可用，**从导航中移除或加 "(演示)" 标签**。

### 3.2 TaskGraphView —— 示例 DAG

**路由**：`/task-graph`，props 直接传入 `createMockTaskDag()`

**现象**：展示的 DAG 图是 `mock-task-dag.ts` 中写死的示例数据，与用户实际执行的 agent 任务无关。

### 3.3 StatusView / MonitorView —— 空壳

**路由**：`/status`、`/monitor`

**现象**：两个页面几乎没有真实数据来源。`MonitorView.vue` 只有 1.6KB，基本上是占位组件。

### 3.4 TokenOptimizerPanel —— 无法验证效果

**路由**：`/token-optimizer`

**现象**：界面展示 token 统计、缓存命中率等，但 `token-optimizer.ts` 的 `getCacheStats()` 返回的数据链路未与真实 agent 调用打通，显示的数字可能是 0 或初始值。

## 四、移动端 / Web 端功能差距

### 4.1 Web 版无法使用 stdio agent

这不是 bug 而是平台限制，但**错误提示不友好**：

- 用户在 Web 版添加 stdio agent 时，`buildAgentConfig()` 抛出 `"stdio agents are not supported on this platform"`——但这个错误只在控制台出现，UI 上没有明确的说明。
- 更糟的是：如果用户从桌面版同步配置到 Web 版（通过 localStorage），stdio agent 只是被静默过滤掉（`restrictedTransports()`），用户不知道为什么配置的 agent 不见了。

### 4.2 Web 版文件系统能力缺失说明不足

`fs/read_text_file` 和 `fs/write_text_file` 在 Web 版返回 `-32601 Method not found`。但对于远程 WebSocket agent（agent 在服务器上），这其实是正常的——agent 操作的是服务器文件系统。当前实现对所有非 Tauri 环境一律拒绝，远程 agent 也受影响。

### 4.3 Flutter 移动端功能严重滞后

`acp_ui_flutter/` 项目与 Tauri 前端是两套独立代码，功能不同步：
- Flutter 版可能根本没有 Multi-Agent、Workflow、Gateway 等功能
- 两套 UI 的行为不一致（比如设置页面的布局和选项）

## 五、国际化问题

### 5.1 翻译键缺失

12 个语言文件中，`zh-CN.ts` 有 29KB、`ru-RU.ts` 有 39KB、但 `types.ts` 有 19KB——翻译键数量不一致，说明部分语言文件落后于开发进度。

### 5.2 硬编码文本

部分组件中的 placeholder、error message 直接写死英文，未使用 `$t()` 函数。例如 `App.vue` 中的 aria-label `"Open menu"`。

## 六、构建与运行问题

### 6.1 TypeScript strict mode 下的残留问题

最近一次重构开启了 `strict: true` 和 `noImplicitAny: true`，但 `noUnusedLocals` 和 `noUnusedParameters` 仍为 `false`——说明项目中存在未使用的变量/参数，这些是潜在的逻辑错误（比如定义了变量但忘记使用）。

### 6.2 `vue-tsc --noEmit` 构建耗时

`npm run build` 会先执行 `vue-tsc --noEmit` 做类型检查。在 24,000 行代码 + 42 个 Vue 组件的规模下，这一步可能需要数十秒。建议日常开发使用 `npm run build:only`，CI 中使用完整检查。

### 6.3 首次 `npm install` 后的 Rust 编译

`npm run tauri dev` 首次运行会触发 Rust 编译，包括 `hermes-crates/` 下 7 个 local crate 及其依赖（sqlite3 的 bundled 编译尤其慢）。没有文档说明首次构建预计耗时。
