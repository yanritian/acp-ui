# ACP-UI 功能优化方案

> 本文聚焦**功能层面的体验优化**——在现有功能基础上提升用户效率、降低使用门槛、增强实用性。
> 日期: 2026-06-05

---

## 一、导航与信息架构重组

### 现状问题

当前 25 个路由平铺在侧边栏，用户看到一长串选项。核心功能（Chat、Multi-Agent）和实验功能（Evolution、Pattern）混在一起，没有分组、没有优先级。

### 优化方案：按用户任务分组导航

侧边栏应改为三级结构：

```
📁 对话
  ├── 💬 聊天                    → /chat
  ├── 🤖 多 Agent 协作           → /multi-agent
  └── 📋 会话管理                → /multi-session

📁 Agent 管理
  ├── ⚙️ Agent 配置              → /agent-config
  ├── 🌐 网关设置                → /gateway
  └── 🤖 Bot 配置                → /bot

📁 工作流
  ├── ⚡ 工作流执行              → /workflow
  ├── 🎬 编排面板                → /orchestration
  └── 🔧 工作流编辑器            → /workflow-editor

📁 监控与分析
  ├── 📡 流量监控                → /monitor (TrafficMonitor 内嵌)
  ├── 📊 状态总览                → /status
  └── 📚 执行历史                → /history

📁 实验室 🧪
  ├── 🧠 记忆系统                → /memory
  ├── 🧬 自进化                  → /evolution
  ├── 📖 模式库                  → /pattern
  ├── 🕸️ 协作网络 (Hermes)       → /collaboration
  └── 🪙 Token 优化器            → /token-optimizer
```

**功能收益**：
- 新用户看到 5 个分组而不是 25 个平铺项，认知负荷大幅降低
- "实验室" 标签明确告知用户这些功能不保证稳定
- 分组可折叠，熟练用户常用分组展开、其余折叠

### 实施方式

在 `feature-registry.ts` 中为每个 `FeatureEntry` 增加 `group` 字段，`AppSidebar.vue` 按 `group` 渲染分组。

## 二、Agent 首次使用体验（Onboarding）

### 现状问题

用户首次打开 ACP-UI 时：空白页面，不知道下一步做什么。唯一提示是 "Select an agent from the sidebar or add one in Settings"（在 WelcomeScreen 中）。

### 优化方案：三步引导流程

**第一步：欢迎页引导**

```
┌─────────────────────────────────────┐
│        👋 欢迎使用 ACP UI            │
│                                     │
│  连接 AI 编程 Agent 的统一客户端      │
│                                     │
│  [快速开始] → 引导添加第一个 Agent    │
│  [我有配置文件] → 导入 agents.json   │
│  [探索演示] → 用模拟数据体验界面     │
└─────────────────────────────────────┘
```

**第二步：Agent 添加向导**

不再是打开一个完整的 Settings 面板，而是简化的对话框：
1. 选择 Agent 类型（预设模板列表，如 Copilot / Claude Code / Gemini CLI 等）
2. 配置必要参数（API Key 如果有的话）
3. 一键测试连接

**第三步：首次对话引导**

Agent 连接成功后，自动创建第一个会话并在输入框区域显示引导提示：

```
💡 试一试：
  - "帮我创建一个 React 项目"
  - "解释这个项目的架构"  
  - 输入 / 查看可用命令
```

### 功能收益

将"首次打开 → 完成第一个任务"的时间从 5-10 分钟缩短到 1-2 分钟，显著提升新用户留存。

## 三、Agent 模板市场（预设配置）

### 现状问题

当前预置了 9 个 Agent（Copilot、Claude Code、Gemini CLI 等），都在 README 和默认 `agents.json` 中。但：
- 用户添加新 Agent 需要手动输入 command + args + env
- 没有模板推荐系统
- 没有评分或社区反馈机制

### 优化方案

**内置 Agent 模板库**：在 `AgentConfigView.vue` 中增加"从模板添加"功能：

```typescript
// src/lib/agent-templates.ts
export const AGENT_TEMPLATES = [
  {
    id: 'copilot',
    name: 'GitHub Copilot',
    description: 'GitHub 官方 AI 编程助手，支持多种语言和框架',
    command: 'npx',
    args: ['@github/copilot-language-server@latest', '--acp'],
    requiredEnv: [],  // Copilot 用 GitHub 登录，无需 API Key
    icon: 'copilot',
    tags: ['官方', '推荐', '新手友好'],
  },
  {
    id: 'claude-code',
    name: 'Claude Code',
    description: 'Anthropic 的 Claude 编程 Agent，代码理解能力强',
    command: 'npx',
    args: ['@zed-industries/claude-code-acp@latest'],
    requiredEnv: ['ANTHROPIC_API_KEY'],
    icon: 'claude',
    tags: ['官方', '推荐', '强代码理解'],
  },
  // ... 更多模板
]
```

**功能收益**：
- 降低 Agent 配置门槛（从 "懂 npx 命令行" 降到 "选一个 → 填 API Key → 完成"）
- 为后续的社区模板分享奠定基础

## 四、会话管理的功能优化

### 4.1 会话搜索与筛选

**现状**：`AppSidebar.vue` 中会话列表只是按时间排序的平铺列表，超过 20 个会话后很难找到目标。

**优化**：
- 顶部加搜索框：按会话标题/Agent 名称模糊搜索
- 按 Agent 筛选：下拉菜单选择只看某个 Agent 的会话
- 按时间分组：今天 / 昨天 / 本周 / 更早

### 4.2 会话标题自动生成

**现状**：会话标题默认为 "Session xxx"（基于时间戳），没有任何语义信息。

**优化**：在用户发送第一条消息后，调用一次轻量 LLM（或直接取前 30 个字符）自动生成标题，例如：
- 用户说 "帮我写一个 Python 爬虫" → 标题: "Python 爬虫编写"
- 用户说 "重构这个组件的状态管理" → 标题: "组件状态管理重构"

### 4.3 会话导出与分享

**现状**：没有会话导出功能。用户想保存对话记录只能截屏。

**优化**：增加导出按钮，支持：
- 导出为 Markdown（对话记录，含代码块）
- 导出为 JSON（完整 ACP 消息记录，可被其他工具解析）
- 复制到剪贴板（纯文本摘要）

### 4.4 会话固定（Pin）

**优化**：允许用户将重要会话固定在列表顶部，不受时间排序影响。

## 五、权限系统的功能增强

### 5.1 权限规则模板

**现状**：每个权限请求都需要用户逐一点击批准/拒绝，频繁打断工作流。

**优化**：增加"规则引擎"：
- "始终允许读取工作区文件" → 自动批准 `fs/read_text_file` 在工作区内的调用
- "始终允许执行 `npm test`" → 对特定命令自动批准
- "始终拒绝 `rm -rf`" → 对危险命令自动拒绝
- 所有规则在 Settings 中可查看/编辑/删除

### 5.2 批量权限批准

**现状**：agent 同时发起 3 个文件写入请求时，用户需要点 3 次。

**优化**：如果多个同类型请求同时到达，合并为一个批量审批对话框：勾选需要批准的项 → 一键批准选中的。

## 六、Traffic Monitor 的实用性增强

### 6.1 消息过滤与搜索

**现状**：所有 JSON-RPC 消息按时间流式展示，无法过滤。

**优化**：
- 按方法名过滤（只看 `prompt` 或只看 `permission`）
- 按方向过滤（请求 vs 响应 vs 通知）
- 搜索消息体内的关键字

### 6.2 性能指标展示

**优化**：在每个 prompt 请求旁显示：
- 首 token 延迟（TTFT）
- 总 token 数 / 费用估算
- 响应时间

### 6.3 错误高亮

**优化**：JSON-RPC error 响应以红色高亮显示，并提取 error.message 作为摘要。

## 七、Token 优化器的可操作化

### 现状问题

`TokenOptimizerPanel.vue` 展示统计数据（token 用量、缓存命中率），但这些都是只读的。用户看到数据但不知道能做什么。

### 优化方案

**增加可操作项**：
- "压缩当前上下文" 按钮：手动触发 context compaction
- 设置 token 预算上限：超过后自动触发压缩或暂停
- "清除缓存" 按钮：重置 context 缓存
- Token 用量趋势图：按小时/天展示用量变化

## 八、多语言支持完善

### 8.1 补齐翻译键

**现状**：部分语言文件落后于主语言 (en-US)。需要建立检查机制。

**优化**：
- 在 CI 中添加翻译键一致性检查脚本
- 对缺失翻译键的 UI 显示 fallback 语言（en-US）+ 黄色标记，方便定位
- `types.ts` 中的类型定义应与实际翻译键同步

### 8.2 界面语言自动检测

**优化**：首次启动时根据系统语言自动选择，而不是默认英文。

## 九、设置页面的可用性

### 9.1 当前结构问题

SettingsView (17KB)、GatewaySettings (27KB)、BotSettings (13KB) 三个独立页面各自打开，信息架构割裂。

### 优化方案

**统一设置中心**：左侧 tab 切换
- General（语言、主题、启动行为）
- Agent 管理（列表 + 添加/编辑/删除）
- Gateway（WebSocket/HTTP 端点配置）
- Bot（Telegram/Feishu/Discord 适配器）
- Permissions（权限规则管理）
- Advanced（Token 预算、Context 压缩参数、日志级别）

### 功能收益

用户不用在三个页面间跳转，一次打开即可完成所有配置。

## 十、移动端适配优化

### 10.1 当前的移动端体验

`AppSidebar` 在窄屏下变为抽屉式（已有），但：
- 工作目录输入在手机上很不方便（需要输入绝对路径）
- 没有移动端专属的快捷操作
- 没有利用移动端特性（如分享菜单、深度链接）

### 优化方案

- 移动端增加"最近使用的工作目录"快捷选择列表
- 利用 `acp-ui://connect?url=ws://...` 深度链接跳转
- 移动端支持通过系统分享菜单发送文本到 Agent
- 增加移动端专属的"语音输入"按钮（调用系统语音识别）
