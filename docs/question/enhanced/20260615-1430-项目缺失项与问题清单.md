## 二、CRITICAL 级问题

### C-1. 代码双写——两套完全不同的 Goal/Topology/Reconcile 实现

**【已验证：13 项子声明全部 TRUE，三轮验证一致】**

这是当前项目最严重的结构性问题。`src-tauri/src/` 和 `src-tauri/crates/swarm-engine/src/` 存在同名但**完全不同**的实现，两套代码在字段名、类型签名、API 设计上完全不兼容。

#### Goal 结构体对比

| 维度 | src-tauri/src/goal.rs（主应用） | crates/swarm-engine/src/goal.rs（crate） |
|------|------|------|
| 构造器 | `Goal::new(id, description, completion_condition)` 3 参数 | `Goal::new(id, description, completion_condition, executor)` 4 参数 |
| Worker 字段 | `assigned_worker: Option<WorkerId>` | `executor: String` |
| Token 预算 | `token_budget: Option<u64>` | `token_budget: u64`（非 Option） |
| Token 已用 | `token_used: u64` | `tokens_used: u64`（多了 s） |
| 依赖字段 | `dependencies: Vec<String>`（带 serde alias `depends_on`） | `depends_on: Vec<String>` |
| 父 Goal | `parent_id: Option<String>` | `parent_goal_id: Option<String>` |
| 迭代记录 | `iterations: Vec<IterationRecord>` | `iteration_log: Vec<IterationRecord>` |
| 时间戳 | `u64`（UNIX 毫秒） | `chrono::DateTime<Utc>` |
| 超时字段 | 无 | `per_iteration_timeout_ms: u64` |
| 输出文件 | 无 | `output_files: Vec<String>` |
| serde 标注 | `#[serde(rename_all = "snake_case")]` | 无 |

IterationRecord 内部字段也完全不同：主应用版使用 `worker_output, evaluation, feedback, tokens_used, timestamp: u64, duration_ms: u64`；crate 版使用 `started_at: DateTime<Utc>, finished_at: DateTime<Utc>, execution_output: Option<String>, evaluation_result: EvaluationResult`。

**影响**：前端 TypeScript 类型（goal-api.ts）与 src-tauri/src/goal.rs 完全对齐，但与 swarm-engine crate 完全不兼容。主二进制通过 `pub use swarm_engine::{GoalOutcome, EchoExecutor};` 导入了 crate 的两个类型，但核心 Goal/Reconcile/Topology/QueenLease 使用的是 src-tauri/src/ 自己的版本。

#### Topology 对比

| 维度 | src-tauri/src/topology.rs | crates/swarm-engine/src/topology.rs |
|------|------|------|
| 设计模式 | enum + 函数式 | trait + struct 式 |
| 拓扑类型 | `Topology::Star/Chain/Pipeline` 枚举 | `StarTopology/ChainTopology` 结构体 + `StarTopologyAsync/ChainTopologyAsync` |
| Pipeline | `execute_pipeline()` 已实现 | 不存在 |
| 真实执行 | 通过 GoalGraph + ReconcileLoop 真实调度 | 同步版返回**伪造 Converged 结果**；仅 Async 版调用 ReconcileLoop |
| Mutex | `std::sync::Mutex` | `tokio::sync::Mutex` |

**建议**：明确 src-tauri/src/ 为权威版本，让 swarm-engine crate re-export 而非维护独立副本。

## 三、HIGH 级问题

### H-1. ACP Server 是 scaffold 【已验证：TRUE】

`src/lib/acp-protocol/server.ts` 文件头标注 `@deprecated`。`start()` 方法仅打印 warn 日志，不启动真实服务器。`registerDefaultHandlers()` 中的消息处理器有逻辑实现，但由于 `start()` 从未监听端口，处理器永远不会被触发。

**说明**：这是设计意图——前端通过 `connectToBackend()` 连接 Tauri 后端，ACP Server 类是为纯 Web 模式预留的。

### H-2. QueenJudgment 在 ConditionEvaluator 中返回 false 【已验证：TRUE，属于设计意图】

`src-tauri/src/goal_evaluator.rs` 中 `CompletionCondition::QueenJudgment` 的 `passed` 字段硬编码为 `false`。注释说明"需要实时 Queen Worker 评估，应由 ReconcileLoop 处理"。这是**有意设计**——QueenJudgment 由 ReconcileLoop 的 `eval_queen_judgment()` 在实际 Worker 上评估，ConditionEvaluator 作为静态评估器不负责此类动态条件。

### H-3. swarm-engine crate topology 同步版是假实现 【已验证：TRUE，已标 deprecated】

`crates/swarm-engine/src/topology.rs` 中 `StarTopology::execute()` 和 `ChainTopology::execute()`（Topology trait 的 impl）直接返回 `GoalOutcome::Converged { iterations: 1, tokens_used: 1000 }` 不执行任何操作。只有 `StarTopologyAsync` 和 `ChainTopologyAsync` 才调用了真正的 ReconcileLoop。代码已标注 `DEPRECATED (H-3): Stub implementation`。

> 注：原 H-4（swarm-orchestrator.ts 孤立死代码）经验证该文件已不存在，已从问题列表移除。

## 四、MEDIUM 级问题

### M-1. TypeScript ShardGroup 类型缺失 shards 字段

TS 侧的 `ShardGroup` 接口只有聚合统计字段（shardCount、completedCount 等），缺少 Rust 侧 `shards: HashMap<String, TaskShard>` 字段。

### M-2. 残留 mock 数据和 TODO

| 文件 | 问题 |
|------|------|
| `stores/agent-realtime.ts` | 硬编码 3 个 mock agent（mock-1、mock-2、mock-3） |
| `stores/token-optimizer.ts` | 包含 initMockHistory、getMockStats 等 mock 方法 |
| `lib/collaboration/mock-data-generator.ts` | 完整的 mock 数据生成器类 |
| `lib/orchestrator.ts` | TODO: trigger actual agent execution |
| `lib/self-improvement/adaptive-strategy.ts` | 硬编码 0.8 替代真实成功率计算 |
| `lib/workflow/dynamic-workflow-engine.ts` | TODO: Replace with vm2 / isolated-vm |

### M-3. 路由中有 Demo 页面

router.ts 中标记 `meta: { isDemo: true }` 的路由：`/status`、`/monitor`、`/hermes`、`/task-graph`、`/collaboration`、`/token-optimizer`。其中 `/task-graph` 使用 `createMockTaskDag()` 生成假数据。

### M-4. reconcile.rs 同步阻塞

src-tauri/src/reconcile.rs 的 `reconcile_once()` 是同步方法，使用 `std::thread::sleep` 轮询，会阻塞调用线程。总纲要求异步非阻塞执行。crate 版本的 reconcile 是 async 实现（`reconcile_goal` async fn），但因为双写问题未被主应用使用。

### M-5. ~~CI 缺少 cargo test~~ 【已验证：不存在此问题】

ci.yml 第 49 行已包含 `cargo test --workspace` 步骤，与 `cargo check`、`cargo clippy`、`cargo fmt --check` 一起执行。此项已关闭。
