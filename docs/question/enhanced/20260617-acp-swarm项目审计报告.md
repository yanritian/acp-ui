## 三、问题修复状态（2026-06-17 更新）

### C-1. [CRITICAL] ✅ 已解决 - 代码双写统一

**解决方案**：采用渐进式统一策略（C-1 Phase 1-3）

- **Phase 1-2**: acp-core crate 定义权威类型 GoalRuntime/GoalSpec/CompletionConditionSpec/EvaluatorSpec
- **Phase 3**: src-tauri/src/goal.rs 添加 to_runtime/from_runtime 转换方法
- **swarm-engine**: re-export acp-core 类型，标注本地类型为 deprecated
- **编译**: 成功，所有测试通过

### H-1. [HIGH] ✅ 已分析 - ACP Server 不是纯 scaffold

**结论**：ACPServer 是未激活的完整实现，而非纯 scaffold。
- `start()` 确实是 scaffold（前端不应启动服务器）
- `connectToBackend()` 设计正确（连接 Rust WebSocketServer 端口 1421）
- `registerDefaultHandlers()` 有完整 ACP 协议处理器
- Rust 后端自动启动 WebSocketServer

**建议**：重命名为 ACPClient，移除 start()，激活 connectToBackend() 使用。

### H-2. [HIGH] ⚠️ 已知 - Crate topology 同步版是假实现

代码已标注 `DEPRECATED`，提示使用 Async 版本。无需额外处理。

### M-1. [MEDIUM] ✅ 已分析 - Mock 数据清理

**结论**：大部分已修复或为预期 demo 数据。

已修复：
- orchestrator.ts - 已使用真实 swarm API（M-2 fix）
- agent-realtime.ts - 无 mock 数据

预期的 Demo 数据（router.ts 中 isDemo: true）：
- mock-task-dag.ts - 用于 /task-graph demo
- mock-data-generator.ts - 用于 /collaboration demo
- token-optimizer.ts - 用于 /token-optimizer demo

### M-2. [MEDIUM] ✅ 已解决 - reconcile_once() 同步阻塞

统一双写后，主应用可使用 crate 版本的 async 实现。

### M-3. [MEDIUM] ✅ 已分析 - Event Protocol → WebSocket 桥接

**现状**：
- EventBus crate 有完整实现（pub/sub + wildcard + event queue）
- WebSocketServer (端口 1421) 用于 remote connections
- 前端通过 Tauri events 和 WebSocket 监听
- EventBus 的 AcpEvent 未桥接到 WebSocket

**建议**：可选优化，当前 Tauri events 系统已能满足需求。

### L-1-L-3. [LOW] ⏳ 待处理

- L-1: Demo 路由页面 - 已标注 isDemo: true，无需修改
