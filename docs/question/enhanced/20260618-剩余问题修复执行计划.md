## 一、C-1 代码双写统一（CRITICAL，预计 2 天）

这是唯一阻塞性问题。两套 Goal/Topology/Reconcile/QueenLease/GoalGraph 实现必须统一为一套。

### 1.1 现状分析

```
src-tauri/src/                     crates/swarm-engine/src/
├── goal.rs (主版本，TS 对齐)       ├── goal.rs (独立实现，字段名/类型不同)
├── goal_graph.rs                   ├── goal_graph.rs
├── goal_evaluator.rs               ├── goal_evaluator.rs
├── reconcile.rs (同步)             ├── reconcile.rs (async)
├── topology.rs (enum+函数式)       ├── topology.rs (trait+struct式，同步版假实现)
├── queen_lease.rs (500行)          ├── queen_lease.rs (310行精简版)
                                    ├── skill_registry.rs (仅此版本有)
                                    ├── complex_executor.rs (仅此版本有)
```

主应用（src-tauri/src/）是权威版本：与 TS 前端对齐、被 Tauri 命令直接调用。
crate 版本是 GLM5/Qwen 独立生成的，有自己的类型系统和 API。

### 1.2 统一方案

**策略：将共享类型提取到 acp-core crate，两边都依赖它。**

选择 acp-core 作为类型宿主的原因：
- acp-core 已经是两个 crate 都依赖的公共协议 crate
- acp-core 当前只有 ~500 行，容量充足
- 避免 src-tauri 和 swarm-engine 的循环依赖

#### 步骤 1：在 acp-core 中创建 goal_types.rs

将以下内容从 `src-tauri/src/goal.rs` 移入 `acp-core/src/goal_types.rs`：

```rust
// 从 src-tauri/src/goal.rs 移入的类型：
pub struct Goal { ... }                          // 15 个字段
pub enum CompletionCondition { ... }              // 8 个变体
pub enum Evaluator { ... }                       // 4 个变体
pub enum GoalStatus { ... }                      // 8 个变体
pub struct IterationRecord { ... }
pub struct EvaluationResult { ... }
pub struct ConditionResult { ... }
pub struct GoalGraphSummary { ... }
```

在 acp-core/src/lib.rs 中添加：
```rust
pub mod goal_types;
pub use goal_types::*;
```

#### 步骤 2：src-tauri/src/goal.rs 改为 re-export

```rust
// src-tauri/src/goal.rs 替换为：
pub use acp_core::goal_types::*;

// 保留仅属于主应用的 impl 块（如有）
// 保留 now_ms() 等辅助函数
```

#### 步骤 3：swarm-engine/src/goal.rs 改为 re-export

```rust
// crates/swarm-engine/src/goal.rs 替换为：
pub use acp_core::goal_types::*;

// 保留仅属于 crate 的类型：
pub struct GoalOutcome { ... }    // 如果 acp-core 没有
pub struct EchoExecutor { ... }   // 测试用执行器
```

#### 步骤 4：统一 Topology

crate 版本有 StarTopologyAsync / ChainTopologyAsync（真实执行），主应用版本有 execute_star / execute_chain / execute_pipeline（也是真实执行）。

**合并策略**：
- 保留主应用的函数式 API（execute_star, execute_chain, execute_pipeline）
- 将 crate 的 Async 版本中的 reconcile_graph() 逻辑合并到主应用的 ReconcileLoop
- 删除 crate 的 trait+struct 式 Topology（同步版已标 DEPRECATED）
- 如果 Async 版本有独特功能，移入主应用 topology.rs

#### 步骤 5：统一 Reconcile

主应用版本（同步，SwarmAgentAdapter）vs crate 版本（async，WorkerExecutor + EchoExecutor）。

**合并策略**：
- 保留主应用的 SwarmAgentAdapter trait（它是真实的 Claude/Codex 适配器接口）
- 将 crate 的 async reconcile_goal() 逻辑合并到主应用，作为 reconcile_once() 的 async 版本
- EchoExecutor 移入主应用的测试模块
- WorkerExecutor trait 可以保留为测试接口

#### 步骤 6：统一 QueenLease 和 GoalGraph

QueenLease：保留主应用的 500 行版本（含 AntiSplitBrain），删除 crate 的 310 行精简版。
GoalGraph：保留主应用版本（TS 对齐），删除 crate 版本。

#### 步骤 7：更新 lib.rs 导入

```rust
// src-tauri/src/lib.rs — 不再需要从 crate 导入 GoalOutcome
// 如果 GoalOutcome 已移入 acp-core，则：
pub use acp_core::GoalOutcome;
// 如果 EchoExecutor 移入测试模块：
#[cfg(test)] pub use swarm_engine::EchoExecutor;
```

#### 步骤 8：编译验证

```bash
cargo check --workspace        # 确认编译通过
cargo test --workspace         # 确认所有测试通过
cargo clippy --workspace -- -D warnings  # 确认无警告
```

### 1.3 风险与注意事项

- **serde 兼容性**：主应用版本有 `#[serde(rename_all = "snake_case")]`，crate 版本没有。统一后确保序列化格式与 TS 前端兼容。
- **chrono vs u64 时间戳**：crate 版本用 `DateTime<Utc>`，主应用用 `u64`。统一为主应用的 `u64` 版本（与 TS 对齐）。如果 crate 内部需要 DateTime，在 crate 内部做转换。
- **测试迁移**：crate 版本的内嵌测试需要迁移到主应用版本或 acp-core。
- **EchoExecutor / GoalOutcome**：这两个类型被 lib.rs 从 crate 导入，需要确保迁移后路径正确。
